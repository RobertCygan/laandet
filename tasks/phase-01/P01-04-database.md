# P01-04 — Database schema, migrations, roles and seeds

## GOAL
Turn the validated reference schema into Drizzle schema files and committed SQL migrations for the Phase 01 tables.
Separate the migration and runtime database roles. Add idempotent seeds.

## CONTEXT
- `db/schema-draft.sql` was applied to PostgreSQL 16, and `db/schema-checks.sql` passed all 23 checks on 25.10.2026 (`docs/DATA_MODEL.md` §9).
- Phase 02/03 tables (bookings, contracts, condition, disputes, reviews, moderation details) are added by their own tasks.

## INPUT
- `db/schema-draft.sql` sections 1–3, 9 (`reports`) and 10, `docs/DATA_MODEL.md`, D-009, D-022.
- Seed sources:
  - localities (D-029)
  - categories (`docs/PROHIBITED_ITEMS.md` §2, including `allow_paid_rental` and safety notices in nb and en)
  - feature flag defaults (`ARCHITECTURE.md` §4.10)
  - demo content (`design/prototype/demo-content.json`)

## OUTPUT
1. `src/db/schema/*.ts`, one file per module, matching the reference SQL:
   - names, types and checks;
   - money as `bigint` with `mode: 'bigint'`;
   - generated columns `value_category` and `search_vector` via `sql`.
2. Better Auth tables generated by the Better Auth CLI and **reconciled** with the reference columns:
   - UUID ids (`advanced.database.generateId: 'uuid'`);
   - table names `users`, `sessions`, `accounts`, `verifications`, `two_factors`, `rate_limits`.
3. `drizzle/0000_*.sql` and onwards: reviewed SQL migrations with extensions (`pg_trgm`, `btree_gist`), constraints, indexes and grants. Each file has a header comment `-- rollback:` describing the manual rollback.
4. Two connection settings:
   - `DATABASE_MIGRATION_URL` (role `laandet_owner`), used only by `npm run db:migrate`;
   - `DATABASE_URL` (role `laandet_app`), used by app and worker.
5. `scripts/seed.ts`:
   - idempotent upserts of localities, categories and feature flags;
   - `--demo` adds demo listings (`is_demo = true`), with a fictional demo owner account `demo@laandet.invalid` (cannot sign in), declared values added, images copied from `design/prototype/images/`;
   - **excludes the prohibited `minigraver` wanted listing**.
6. CI job `db`:
   - service `postgres:17`;
   - runs migrations, then an adapted `schema-checks` for the Phase 01 tables, then `drizzle-kit check` (no drift).

## CONSTRAINTS
- No destructive migrations. Changes follow expand → migrate → contract.
- The runtime role never gets `UPDATE`/`DELETE` on `audit_events` or `legal_acceptances`, or writes on `legal_document_versions`.
- No real personal data in seeds.

## TESTS (acceptance criteria)
1. Migrations apply cleanly on an empty PostgreSQL 17 database in CI.
2. `drizzle-kit check` reports no drift between schema files and migrations.
3. **Privilege tests**, connected as `laandet_app`:
   - `UPDATE audit_events` fails;
   - `INSERT INTO legal_document_versions` fails;
   - `INSERT INTO listings` succeeds.
4. Constraint tests ported from `db/schema-checks.sql` for the listing rules (A/B classification, deposit ≤ value, give-away free with defects, published offer has a handover option) pass.
5. Running `npm run db:seed` twice gives the same row counts. The categories seed contains `tilhengere`, `sykler` and `padling` with `allow_paid_rental = false`.
