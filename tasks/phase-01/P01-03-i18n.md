# P01-03 — i18n foundation (Norwegian Bokmål + English)

## GOAL
Centralise all interface strings and support `nb` (default) and `en` from day one, with Norwegian formats for
money and dates (D-001).

## CONTEXT
- Master spec §2 requires centralised strings and the formats `1 500 kr` and `14.12.2026`.
- The owner asked for Norwegian and English.
- English legal translations exist in `legal/en/`; the Norwegian text prevails.

## INPUT
- `next-intl` 4.x
- the term glossary in the English translation brief (also see `legal/en/` headers)
- `docs/ARCHITECTURE.md` §4.9

## OUTPUT
1. `src/i18n/routing.ts`:
   - locales `['nb','en']`, default `nb`, `localePrefix: 'as-needed'`, so `nb` has no prefix and English is under `/en`;
   - Norwegian slugs used for both locales, for example `/en/utforsk`.
2. `messages/nb.json` and `messages/en.json`, split by namespace (`common`, `nav`, `home`, `listing`, `auth`, `profile`, `legal`, `errors`).
3. `src/i18n/format.ts`:
   - `formatKr(ore: bigint): string`, giving `1 500 kr` in both locales;
   - `formatDate(d)` giving `14.12.2026`;
   - `formatDateTime(d)` giving `14.12.2026 kl. 10:00` (nb) or `14.12.2026, 10:00` (en);
   - all in the time zone `Europe/Oslo`.
4. Language switcher in header and footer. The choice is stored in the `NEXT_LOCALE` cookie and, for signed-in users, in `user_profiles.locale` (after P01-04).
5. `docs/GLOSSARY.md`: nb ↔ en UI terms (Leies ut = For rent, Ønskes leid = Wanted, Gis bort = Giving away, …).

## CONSTRAINTS
- No hard-coded user-facing strings in components. A lint rule or review checklist enforces it.
- User-generated content is never machine-translated.
- Legal pages in English show the banner «The Norwegian version prevails».

## TESTS (acceptance criteria)
1. **Unit `formatKr`:**

   | Input (øre) | Expected |
   |---|---|
   | `0n` | `0 kr` |
   | `15000n` | `150 kr` |
   | `150000n` | `1 500 kr` |
   | `123456789n` | `1 234 567,89 kr` |

   The thousands separator is asserted explicitly: non-breaking space U+00A0 is the `nb-NO` Intl output, and the test documents which one is used. No floating-point maths: the test passes values above 2^53 øre.
2. **Unit:** every key in `nb.json` exists in `en.json` and the other way round (parity test), with no empty strings.
3. **e2e:** switching to English changes navigation labels; reloading keeps English; `/en/utforsk` renders.
